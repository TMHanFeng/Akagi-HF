# 坐标校准工具

这一版说明里所有坐标都是在这台机器上**实测**出来的，工具也一起放这儿 ——
万一雀魂改了 UI，你可以自己重新量一遍。

所有坐标都是 **16:9 归一化坐标**，相对**游戏 canvas**（不是窗口）：

```
x_norm = (px - canvas_left) / canvas_w * 16
y_norm = (py - canvas_top)  / canvas_h * 9
```

## 前提

* Python 3 + `Pillow`（`pip install pillow`）。
* 这些脚本操作的是 **AkagiMS 的窗口**（标题必须精确等于 `AkagiMS`），
  用来在**同一款客户端**上量坐标 —— 和 v3 自己开的浏览器是同一套画布几何。
* 脚本会**真的点鼠标**。`click_norm.py` 只接受归一化坐标，
  而且窗口尺寸和测量时不一致会**拒绝点击**（免得点歪）。

## 用法

```bash
# 1. 抓一张当前窗口的图（会先把窗口置前，PrintWindow 对后台窗口是全黑）
python snap_game.py <输出目录>

# 2. 放大看某个区域，找按钮的像素框
python crop.py <图.png> <输出.png> <x0> <y0> <x1> <y1> [放大倍数]

# 3. 找金色按钮（「確定」「再來一場」都是金色字 / 蓝色板上的金色字）
#    同时解出 canvas 矩形，输出归一化坐标
python find_button.py <图.png>

# 4. 找灰色 / 浅色的关闭控件（各面板右上角那个 X）
python find_close2.py <图.png> <x0> <x1> <y0> <y1> [最低亮度]

# 5. 直接点某个归一化坐标（真鼠标事件）
python click_norm.py <x_norm> <y_norm> [--label 名字]

# 6. 滚轮 / ESC
python scroll_at.py <x_norm> <y_norm> <格数>   # 正数向上
python press_esc.py
```

## 看 wire 日志

`wire_log.py` 解析 AkagiMS 的原始 WS 帧，用来确认「点下去到底发生了什么」：

```bash
# 默认读 logs/<最近一次>/inspector.jsonl，也可以自己指定
python wire_log.py <log路径> 2026-11-20T15:48:40 2026-11-20T15:49:40
```

输出里最关键的两个方法：

* `.lq.Lobby.startUnifiedMatch` —— **客户端请求开局**（点中了）；
* `.lq.Route.requestRouteChange` 的 `route_id` ——
  `route-2` = 段位場大厅、`route-3` = 匹配准备、`route-4` = **大厅**、`route-5` = 对局中。

`route_timeline.py` 把整个会话的路由切换、开局请求、界面阶段汇成一条时间线，
用来确认「点完结算画面到底走到了哪里」：

```bash
python route_timeline.py
```

## 用 CDP 直接驱动 v3 自己的浏览器（最直接的调试手段）

v3 拉起的游戏浏览器开着 CDP（`--remote-debugging-port`，**端口每次随机**）。
`cdp.py` 会自己找到那个端口，然后就能读页面、截图、**按归一化坐标点击** ——
而且走的是和模块**完全同一条**路径（`Input.dispatchMouseEvent`：hover → press → release），
所以它点得动，就说明模块点得动。

```bash
# 画布几何 + 视口（先看这个，确认画布位置和大小）
python cdp.py rect

# 截图当前页面
python cdp.py shot out.png

# 在任意 JS 表达式上跑一下（比如看页面里有什么元素）
python cdp.py eval "document.title"

# 按 16:9 归一化坐标点击游戏画布 —— 和说明书里的四个坐标同义
python cdp.py click 14.59 8.37 --shot after.png   # 結算画面的「確定」
python cdp.py click 12.23 8.34 --shot after.png   # 道具面板的「再來一場」
python cdp.py click 6.58 6.71  --shot after.png   # 對話框裡的「確定」
python cdp.py click 10.87 7.10 --shot after.png   # 匹配準備畫面的「匹配對局」

# 只算落点不点（校准坐标时用）
python cdp.py click 14.59 8.37 --no-click
```

> 需要 `pip install websocket-client`。
> `cdp.py rect` 的输出里 `canvases[0]` 就是游戏画布：
> `x / y` 是它在视口里的左上角，`w / h` 是 CSS 像素尺寸，
> `cw / ch` 是绘制缓冲（恒为 2560×1440）。
> 模块按 `page_x = canvas.x + norm_x / 16 * canvas.w` 换算，
> 所以**换窗口大小不用重新校准坐标**。

> ⚠️ 2026-11-20 实测坐标在 v3 自己的浏览器里**同样命中**：
> 画布 1036×582、`y = 95`，于是「確定」落在 (944.7, 636.3)、
> 「再來一場」落在 (791.9, 634.3)、對話框「確定」落在 (426.1, 528.9) ——
> 三个都在按钮本体内。

## ⚠️ 注意事项

* **不要在大厅里点「確定」的坐标 (14.59, 8.37)** —— 实测那会把客户端送进段位場并开一局。
* **不要点段位場列表里的房间条目** —— 点了就开真对局。
* 大厅里的「再來一場」坐标 (12.23, 8.34) 和对话框「確定」坐标 (6.58, 6.71) 是**惰性**的，
  在大厅点它们什么都不会发生 —— 但仍然别在结算流程之外乱点。
* **`PrintWindow` 偶尔会抓到陈旧帧** —— WebView2 的画面不是每次都刷新。
  拿抓屏当证据时，务必用「点了之后有没有真的变化」或 wire 日志来复核。
